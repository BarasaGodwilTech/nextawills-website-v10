How we work

From brief to running system.

The same four stages run whether it's a single hosting account or a full custom build — what changes is the depth of each one, not the order.

Start at Stage 01See it in practice ↓

The four stages

  • 01 · Scope
  • 02 · Provision
  • 03 · Launch
  • 04 · Maintain

Stage 01

Scope

We map what you actually need — traffic, storage, client count, or feature list — before recommending a plan or writing a proposal. For software, this stage ends with a written scope and price, agreed before any code is touched.

Stage 02

Provision

Servers, domains, and DNS are configured and tested in a staging environment. For software builds, this is where the first working version goes up on a staging link — feedback happens continuously here, not at the very end.

Stage 03

Launch

DNS is cut over or the account goes live, with monitoring switched on from minute one. You get full documentation and access — no black boxes, no vendor lock-in you don't understand.

Stage 04

Maintain

Ongoing monitoring, backups, and a direct line to support as you grow — plus a clear path to scale up resources or add features without a disruptive migration.

In practice

What this looks like for a software build.

Scope call

We agree on pages, features, and integrations before any code is written, and send a written scope and price.

Build in the open

You get a staging link early — feedback happens continuously, not at the end of the build.

Handover

Source code, documentation, and access are yours — no dependency on us to make future edits.
